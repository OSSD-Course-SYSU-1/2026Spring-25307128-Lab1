# HarmonyOS 自由流转可演示版本

当前功能定位为“自由流转可演示版本 + HarmonyOS 分布式能力接口接入”。项目已接入真实分布式相关 API，用于支持真实设备环境下的自由流转；同时考虑到当前测试环境主要为模拟器，无法稳定完成真实设备发现和同步验证，因此提供本地演示模式用于课堂或项目验收中展示代办任务、当前专注状态的流转业务流程。本功能不是完整商用云同步，也不包含多人协作、云端冲突合并或长期后台同步能力。

## 使用的 HarmonyOS API

- `distributedDeviceManager`
  - 用于在真实设备环境下获取当前可用或可信的分布式设备列表。
- `distributedKVStore`
  - 用于写入任务流转、专注状态流转的 JSON payload。
- `SingleKVStore.sync(..., PUSH_ONLY, ...)`
  - 用于向目标设备发起单向同步。
- `SUBSCRIBE_TYPE_REMOTE`
  - 用于接收端监听远端 KV 数据变化。
- `ohos.permission.DISTRIBUTED_DATASYNC`
  - 用于申请分布式数据同步权限。

以上接口已经接入项目代码。模拟器环境下，这些接口可能无法稳定完成真实设备发现、可信设备关系建立和完整分布式同步链路验证。

## 支持流转内容

当前支持两类内容：

1. 代办任务
   - 任务名
   - 任务类型
   - 优先级
   - 截止日期
   - 分类
   - 重复类型
   - 已专注次数与分钟数
   - 计划专注时长

2. 当前专注状态
   - 当前专注任务名
   - 剩余时间
   - 总时长
   - 是否暂停
   - 来源设备
   - 发送时间

接收专注状态后，当前版本不强制恢复剩余倒计时，而是提供“以完整时长重新开始专注”，避免多设备时间差导致计时状态混乱。

## 演示入口

- 代办任务更多菜单 -> 流转到其他设备
- 专注空间 -> 流转当前专注

## 兜底演示流程

当真实设备发现失败、模拟器环境不支持完整分布式发现，或 `sync` 调用不可用时，服务层会进入本地演示模式。

兜底流程：

1. 点击“流转到其他设备”或专注空间中的“流转”。
2. 未发现真实设备时，设备选择面板会显示“演示设备”。
3. 应用显示接收卡片。
4. 如果接收的是代办任务，可以选择：
   - 加入我的代办
   - 立即开始专注
   - 忽略
5. 如果接收的是专注状态，可以选择：
   - 以完整时长重新开始专注
   - 忽略

本地演示模式会在页面状态中标记为“演示设备”或“兜底演示”，用于验证任务流转和专注流转的业务逻辑，包括接收卡片、加入我的代办、立即开始专注等交互。该模式用于课堂演示和录屏，不等同于真实设备环境下的数据同步链路。

## 真机验证条件

真实分布式链路需要在真机环境中验证，建议满足以下条件：

1. 两台 HarmonyOS 设备。
2. 两台设备安装同一 App。
3. 登录同一华为账号，或已建立可信设备关系。
4. Wi-Fi / 蓝牙已开启。
5. App 已授权分布式数据同步权限。
6. 接收端 App 保持打开，便于监听远端 KV 变更。

满足上述条件后，发送端可通过 `distributedDeviceManager` 发现设备，写入 `distributedKVStore`，并通过 `SingleKVStore.sync(..., PUSH_ONLY, ...)` 发起同步。接收端可通过 `SUBSCRIBE_TYPE_REMOTE` 监听远端数据并显示接收卡片。文档仅说明项目已接入相关接口，并支持在真实设备环境下验证自由流转能力。

## 模拟器环境限制

当前主要测试环境为模拟器，存在以下限制：

1. 无法稳定发现真实 HarmonyOS 设备。
2. 无法保证建立同账号或可信设备关系。
3. 无法完整模拟分布式 KV Store 的跨设备同步链路。

因此，模拟器环境采用本地演示模式验证业务流程；真实设备发现与数据同步需要在满足条件的 HarmonyOS 真机环境中验证。

## 边界说明

当前版本不实现：

- 商用云同步
- 多人协作
- 冲突合并
- 后台长期同步
- 精确恢复跨设备倒计时

这些能力可以作为后续扩展方向，但不属于当前自由流转演示版范围。
