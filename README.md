# 鸿蒙待办清单工程文件结构解析
## 一、工程整体架构说明
本工程是基于HarmonyOS ArkTS声明式开发的轻量化待办清单应用，采用标准鸿蒙应用工程结构，整体分为「应用入口模块」「页面交互模块」「资源配置模块」三部分，实现了待办事项的添加、删除、修改基础功能。

## 二、核心文件夹解析
1.  `entry/`：主应用模块，工程的核心目录，包含所有业务逻辑与页面代码
    - `src/main/ets/`：ArkTS代码的根目录，存放页面、组件、工具类等代码文件
    - `src/main/resources/`：资源文件目录，存放应用的图标、字符串、颜色、布局等静态资源
    - `src/main/module.json5`：应用模块配置文件，声明应用的页面路由、权限、组件等信息
2.  `oh-package.json5`：项目依赖配置文件，声明工程所需的鸿蒙SDK版本、第三方依赖包等信息
3.  `build-profile.json5`：工程编译配置文件，配置编译选项、签名信息、产品配置等内容

## 三、关键代码文件解析
1.  `entry/src/main/ets/pages/Index.ets`：应用首页主文件，实现了待办清单的核心UI与交互逻辑
    - 核心组件：`List`列表组件，用于渲染待办事项列表
    - 核心状态变量：`@State todoList: string[]`，存储待办事项数据，状态变更时自动刷新UI
    - 基础交互逻辑：`TextInput`输入框获取用户输入，点击按钮添加待办项；列表项点击删除功能
2.  `entry/src/main/module.json5`：页面路由配置，将`Index.ets`声明为应用的默认启动页面
3.  `entry/src/main/resources/base/element/string.json`：字符串资源文件，统一管理应用内的文本内容，方便多语言适配

## 四、工程运行逻辑
应用启动时，系统加载`Index.ets`作为默认页面，初始化待办事项列表；用户通过输入框添加任务，数据存储在状态变量中并实时渲染到列表；用户可点击列表项删除任务，状态变量变更后自动更新页面显示。
